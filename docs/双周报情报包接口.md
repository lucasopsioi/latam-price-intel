# 双周报情报包接口（中枢 ⇄ 拉美双周报工作台）

> 场景：情报中枢 24 小时抓取只能在**家里电脑**跑；**公司电脑**没有 `intel.db`。
> 双周报工作台需要竞品数据，所以两边约定一个都认的文件格式——「竞品情报包」。

## 一句话流程

```
家里电脑（中枢）                                  公司电脑（工作台）
python main.py export-pack --period 2026-W35  →  U 盘/网盘  →  竞品页「导入情报包」
        exports\竞品情报包_2026-W35_…json                          → 覆盖矩阵 / 促销 / 上市 / 价格变动 全部照常
                                                                  → 中枢周报正文进「素材登记簿」，由 Agent 归稿
```

每周导出一次即可；导出的包始终覆盖**当前双周期次的完整窗口**（截至导出日），
公司电脑导入最新的一个就行，不用合并。

## ★ 核心纪律：SQL 只有一份

所有查询的 SQL 在工作台的 `app/core/intel-sql.js`。工作台运行

```
node scripts/build-sql-bundle.js
```

会生成 `intel-sql-bundle.json` 并**同时写一份到本目录 `tools/`**。
本目录的 `tools/export_biweekly_pack.py` **不写任何 SQL**，只做两件事：照单执行 + 打包。

包里带每条 SQL 的指纹（`sqlHash`）与整体指纹（`bundleHash`）。
工作台导入时逐条核对；指纹不同的板块**不会被采用**，界面明示"口径可能不同"。
所以两边软件版本不同步时不会静默出错数，只会明确拒绝。

## 只读三防线

`intel.db` 是不可再生的观测存档。导出器：

1. `file:…?mode=ro` 打开
2. `PRAGMA query_only=1`
3. **真的试一条 `CREATE` 与 `INSERT`，必须被拒**——结果写进包的 `readOnlyProof`

只验"能读"不算证明。工作台校验时若包里没有 `writeRejected: true` 会提示。

## 窗口推导（两边逐字一致）

```
curEnd   = min(dataAsOf, period.windowTo)
curStart = curEnd − 13 天
prevEnd  = curStart − 1 天
prevStart = prevEnd − 13 天
```

健康采集日**只影响"可比不可比"**，不影响窗口边界。所以这里不移植工作台的
`planWindow`，只把 `dayHealth` 的行原样带回去，工作台自己判可比性。

## 包的形状（schemaVersion 1）

```json
{
  "schema": "latam-intel-pack", "schemaVersion": 1,
  "generatedAt": "2026-09-01T17:18:21", "generator": {"name": "hub-python"},
  "bundleHash": "bundle@ewqbxc",
  "period":  {"id": "2026-W35", "windowFrom": "2026-08-17", "windowTo": "2026-08-30",
              "cutoff": "2026-08-30", "publish": "2026-09-03"},
  "window":  {"dataAsOf": "2026-09-01",
              "cur": {"start": "2026-08-17", "end": "2026-08-30"},
              "prev": {"start": "2026-08-03", "end": "2026-08-16"}},
  "hub":     {"dbMeta": {...}, "dbBytes": 248000000, "dbPath": "intel.db"},
  "boards": {
    "dbMeta":      {"query": "dbMeta",      "sqlHash": "dbMeta@…",      "params": {}, "rows": [...], "flags": {...}},
    "dayHealth":   {"query": "dayHealth",   "sqlHash": "…", "params": {"winStart": "…", "winEnd": "…"}, "rows": [...]},
    "coverage":    {...}, "promoBoard": {...}, "promoPrev": {"query": "promoBoard", ...},
    "launchCards": {...}, "priceMoves": {...}
  },
  "digest":  {"weeklyReports": [{"id": 7, "week_start": "…", "title": "…", "highlights": [...], "content_md": "…"}]},
  "readOnlyProof": {"writeRejected": true, "detail": "CREATE… 被拒：attempt to write a readonly database；INSERT… 被拒：…"}
}
```

七个板块与工作台竞品页的现场查询**一一对应、参数逐字相同**（minRows 20 / minPct 2 /
limit 60 与 80 / 回看 60 天与 90 天）。`promoPrev` 是上期窗口的促销板，供环比用。

### digest 是什么、不是什么

`digest.weeklyReports` 是中枢自己（LLM）写的周报正文。它进工作台后**只能当素材**：
存进素材登记簿 → 由人点归稿 → 每个数字过溯源门禁。它不产生任何数据芯片。
板块里的行才是芯片的来源。

## 命令

| 事 | 命令 |
|---|---|
| 导出本期 | `python main.py export-pack` |
| 导出指定期次 | `python main.py export-pack --period 2026-W35` |
| 导到别处 | `python main.py export-pack --out D:\交接` |
| 校验一个包 | `python main.py export-pack --validate exports\竞品情报包_….json` |

期次 = 数据截止落在**奇数** ISO 周周日的双周（W29/31/33/35…），与工作台同一日历。
传偶数周会被拒绝并说明。

## 自动刷新（不用人记着导）

`app/scheduler.py` 里有 `biweekly_pack` 任务：**每天 05:20** 自动导出到 `exports/`，
同时覆盖写一份固定名 **`exports/竞品情报包_最新.json`**（网盘同步 / 计划任务直接拿这个）。
`config` runtime 里 `biweekly_pack.auto = 0` 可关、`biweekly_pack.time` 可改。
misfire 宽限 12 小时：凌晨没开机，开机后补跑。**服务重启后生效**（`tools\restart.ps1`）。

★ 解释器：中枢跑在 `tools\pyenv.cmd` 解析出的 Python（当前是 3.14，装了 apscheduler）。
PATH 上的 `python` 是另一个没有 apscheduler 的 venv——直接 `python -c "from app import scheduler"` 会
ModuleNotFoundError，**这不是任务坏了**。导出器本身只用标准库，任何 Python 3.11+ 都能跑
`python main.py export-pack`。

手动也行：`python main.py export-pack --latest`（同样更新固定名文件）。

## 与工作台的往返测试

工作台仓的 `test/intel-pack-roundtrip.test.js` 在有 `intel.db` 的机器上：
用本导出器真导一个包 → 对每个板块用工作台自己的通道跑同一条 SQL → **行逐字节比对**
→ 工作台校验器与本目录校验器都判"可用" → 两边期次日历一致。
这条测试红了，说明接口契约被破坏（多半是 SQL 改了没重新生成捆绑包）。

## 出问题时

| 现象 | 原因 | 处理 |
|---|---|---|
| `找不到 SQL 捆绑包` | 工作台没生成/没拷 `tools/intel-sql-bundle.json` | 工作台目录跑 `node scripts/build-sql-bundle.js` |
| 工作台说"SQL 指纹不一致" | 两边版本不同步 | 更新其中一边到同版，重新导出 |
| 工作台说"窗口不一致" | 导出时 `--period` 不是公司电脑上的当前期次 | 用正确期次重导 |
| `只读自检失败` | 库被以可写方式打开了（不应发生） | 停下检查，别继续 |
